00 / Identity

One name.
One philosophy.

The name is an architectural statement, not decoration. APOTHEON ONE describes what the platform is intended to do as it grows: converge capability, then continuously elevate what that capability can become.

APOTHEON

Elevation toward the highest attainable form.

Not a fixed feature list. A platform designed to absorb stronger tooling, deeper automation, broader execution, and more capable engineering without losing the discipline of its underlying architecture.

ONE

Convergence into a singular coherent whole.

One environment. One control plane. One operational view across development, security, infrastructure, jobs, CI, recovery, and whatever capabilities are added next.

Unified. Bring the capabilities together.   Elevated. Refuse to stop at their current form.
01 / Unified

One control plane.
Real subsystems.

APOTHEON ONE is built around persistent state and explicit execution boundaries. Projects are provisioned through real framework toolchains, registered with manifests, verified through bounded jobs, and routed to local, containerized, or hosted runners. The security environment shares orchestration and evidence infrastructure while preserving its own operator and target boundaries.

03 / Security

A complete subsystem.
Not a checkbox.

The original security environment remains a first-class domain with its own operator plane, isolated training range, evidence state, research cases, engagement workspaces, defensive pipeline, static triage, and bounded automation.

Explicit boundaries around intentionally vulnerable systems.

Juice Shop, DVWA, and WebGoat bind to loopback and live on an internal Docker network. The disposable Kali operator remains separate and carries the capabilities required for research without granting them to target services.

04 / Automation

Control survives the terminal.

The operating model extends beyond one shell session. Persistent jobs, structured MCP, GitHub-hosted execution, an independent issue bridge, and a wake controller outside the Codespace keep the environment observable and recoverable.

Structured MCP

Approved platform, project, repository, job, service, security, and lifecycle operations without turning the browser into an arbitrary shell.

structured operationspath controls

Out-of-band bridge

Fixed recovery and maintenance tasks remain available independently from MCP so the service that provides automation can itself be repaired.

allowlisted taskstimeouts

External wake controller

Codespace start and restart logic runs in GitHub Actions outside the environment it manages, preserving a recovery path when nothing inside the runtime can answer.
